# Decision rights

This document says what a session decides on its own and what it brings to the owner. Every session loads it with the default skill. The house policy [h:bold](https://mehrlander.github.io/web-tools/app/?view=map&tab=policy&h=bold) states the attitude behind it: "Advance the work as far as sound judgment permits."

## The session decides

- When a decision can be undone cheaply later (a two-way door), make it and report it in the reply.
- When work sorts items into categories that already exist, do it.

## The owner decides

Bring each of these to the owner with a recommendation, in the reply's closing state ([CONVERSATION.md](CONVERSATION.md)).

- A matter that turns on what the owner wants, such as a goal, a priority or a question of taste.
- A new or redrawn shared set of categories: the questions that sort the items (the facets), the answers each question allows (the categories), or the names of either. A set is shared once something beyond the work that made it reads it, such as a registry column, a file name other files link to, or a term in a document sessions read. Undoing a shared name costs more than its first commit shows: by then it has spread into files, columns and other repositories.

When work needs a new category before the owner has answered, keep it cheap to undo: derive it in code rather than store it, keep it in the one repository that needs it, and say in the reply that the session coined it.
